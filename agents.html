Autonomy Policy

Agent

Declare what an automated run may touch, then read the policy back.

You write four files: which projects an automated run may touch, which capabilities are allowed at all, whether web and outbound message actions are approved, and whether the whole thing is in dry run. It reads those back and reports which of the actions you declared pass your own filters. It runs none of them, and it ships with the policy empty on purpose.

  • List the candidate actions you declared that pass your own policy
  • Show which projects and capabilities are currently in scope
  • Report the state of the web and outbound message approval gates
  • Confirm whether the whole thing is still in dry run
Needs Nothing, works offline. You fill in the policy files yourself.

Doctor

Agent

Check whether your install is actually healthy, then fix two of the faults.

It runs five read-only checks on your own install: is the app serving, are your modules intact, is the automation hook registered, is the search index fresh, and are any installs broken. Two of those findings it can put right, by re-running an installer you already listed in your config or rebuilding a stale index. Nothing else gets touched.

  • Check whether your app is serving on the address you configured
  • Verify every installed module still has the files it installed
  • Confirm the automation hook is registered in your settings file
  • Report whether the search index exists and how stale it is
  • Rebuild a missing or stale index using your own rebuild command
  • Re-run the installer for a module that came back broken
Needs Nothing, it reads your own install once you fill in the paths

Evolver

Agent

Notices what you keep repeating and proposes a fix you have to approve.

Evolver watches how you actually work on this machine, spots the same request coming round again, and writes it up as a proposal: a shortcut, a repair, a route worth making permanent. Watching is off until you switch it on, everything stays in a locked folder on your own machine, and nothing is applied until you approve it by token. Its own safety rules cannot be edited by a proposal.

  • Record what you ask for and find the patterns that repeat
  • Surface recurring failures and gaps worth fixing
  • Draft a bounded repair or a shortcut for a weekly routine
  • Hold every proposal until you approve it by token
  • Report exactly what it can and cannot do right now
Needs Nothing, works offline

Identity Ontology

Data

A starter identity map so one person is not three separate records.

The ontology names your records, the stores that hold them, and the safe rules for joining them. It ships one worked example: resolve a contact across a CRM and an address book by matching normalised email first, then phone. It is a small teaching scaffold with synthetic demo data, meant to be replaced with your own entities and rules.

  • Resolve a contact across your identity stores
  • Match on normalised email first, then normalised phone
  • Describe entities, stores and join rules in one registry
  • Try the resolver against synthetic demo data before wiring real records
  • Extend the schema with your own entities and stores
Needs Nothing, works offline

Mac Cleaner

Agent

Finds what is eating your disk, and removes nothing until you confirm.

Mac Cleaner looks only inside the folders you list in its config, and that config ships empty, so a fresh install cannot see any of your files. It reports exact paths and sizes, and applies the backup retention rules you set. Removal takes a second run carrying the confirmation token, and every file is rechecked in the moment before it goes. Deletion is permanent.

  • Audit the folders you configured and show what is taking up space
  • Preview the old files a cleanup would remove
  • Delete those files once you pass the confirmation token
  • Preview which backup archives your retention rules would drop
  • Prune old backup archives after you confirm
Needs A config listing the folders it may look at. No account needed. Asks before it acts

Overseer

Agent

Tells you when something you run has stopped, filled up, or gone stale.

Six checks over the things you configure: services and processes, scheduled jobs, free disk space, log directory size, backup freshness, and env file syntax. All six only read. Two repairs can act, restarting a service you listed and clearing a lock once it is genuinely stale. Both run straight away, and both only touch entries you put in the config yourself.

  • Check whether your configured services and processes are still alive
  • Check whether scheduled jobs have reported in recently
  • Watch free disk space and log directory size against your own limits
  • Check backups are recent and env files are not malformed
  • Restart a stopped service you listed, then verify it came back
  • Clear a lock file once it is past the stale window you set
Needs A config listing the services, jobs, paths and locks you want watched

Parallel Sidecars

Agent

Works out which parts of a job can run in the background at once.

Before a long job starts, this decides which parts can run beside the main thread, how many lanes there should be, and what each one is allowed to touch. It plans only: it never launches a worker and never edits your files. Writable lanes are off by default, and when you turn them on they work in a disposable copy of the repository and hand back a patch to read.

  • Plan which parts of a job can run in parallel
  • Cap how many lanes run and how much each one may touch
  • See the exact gate that held a writable lane back
  • Inspect what a sidecar patch would change before anything is applied
  • Check what this install is currently allowed to do
Needs Nothing, works offline. Git on your PATH for writable lanes
